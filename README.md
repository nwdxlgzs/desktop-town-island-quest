# 电脑小镇 · 岛屿探索 | Desktop Town: Island Quest

面向中小学生的等距体素电脑操作闯关游戏。课程有 **81 个完整工坊任务、243 个操作步骤、40 种题型**。按熟练者每分钟 1.8 个完整工坊安排目标 45 分钟，实际用时需课堂试用校准；游戏没有倒计时。

## 直接游玩

使用现代 Chrome / Edge 打开 `dist/index.html`。脚本、课程、图标、音乐和三维资产都在一个文件中，可复制分发并离线运行。

对外分发游戏时，只需提供 `dist/index.html` 或同内容的 `dist/电脑小镇·岛屿探索.html`，二选一即可。发布源码时保留源码、配置、依赖清单、测试工具和文档；`node_modules/`、`test-results/`、本机环境配置与性能采样文件不属于发布内容。依赖可通过 `npm ci` 重新安装，测试产物按需重新生成。

- 每岛随机安排 **1–6 个工坊**，引导岛为 2–3 个。完成本岛后走到码头，按 E 或点击小船出发。
- 点击整个工坊、实体长台、NPC、小地图编号或工坊目录，角色沿可通行路线前往；近处可按 E。
- WASD / 方向键移动，按住 Shift 跑步；点击目的地的路线超过 13 单位时自动跑。空格播放跳跃动画，沿用地面碰撞，不越墙或跨崖。
- 低台阶可走，高差超过 0.6 单位时需绕行或爬梯子。梯子紧贴崖壁垂直放置，支持点击、靠近按 E 或朝梯口移动；人物先走到梯口，再垂直攀爬、迈上平台，NPC 共享攀爬动作，出生位置接入已验证的小路。靠近 NPC 按 E 互相招手，工坊居民回应后再按 E 开始练习。
- 滚轮缩放，中键拖动地图；按住右键水平拖动可 360° 环视，松手平滑回到主视角。右上角地图按钮查看全岛。航行先拉远、靠岸恢复近景，船身避开海岸和礁石。
- 首次打开会高亮游戏全屏按钮，随后介绍移动、工坊、航线和画面设置；完成或跳过后自动记住。操作手册中的“再看按钮指引”可以重新打开，指引期间暂停活动。
- 沉浸按钮让游戏占满浏览器内容区；Escape 先关闭练习，再退出沉浸。XP、沉浸和声音开关位于游戏内；背景音乐默认关闭，手动开启后保存偏好。
- 建议电脑、键盘与实体鼠标。Mac 支持 ⌘；操作手册和截图练习补充统信 UOS 的 Ctrl + Alt + A，以及从启动器打开截图工具、复制或导入截图的说明。系统中文输入法与系统截图由操作系统处理。

## 随机航程

任务、岛名和景观是三个独立数据池。新冒险使用随机种子组合航程，每岛抽取 1–6 个完整任务包，直到 81 个工坊全部分配。岛屿数量由任务量和每岛容量决定；名称池只有一个名称也能生成完整航程，重复名称附序号。岛名不绑定固定任务、地图或终点。

引导任务靠前，其余任务包随机排列；每工坊三步仍按原顺序，不丢失、不重复。刷新和回访使用同一存档种子。地图随工坊数量、景观和疏密设置调整面积，拥挤时扩大重排。每座岛可以采用疏散、混合或聚落式布局。

岸线用随机凸岬、凹湾和多频起伏生成，不局限于固定几何形状。整座岛从海面升起，岩岸有分层颜色与随机 1–5 层厚度；局部有一两层低岸、厚岩壁、自然高台、缓坡和陡崖。码头和溪流岸边保留较低的通行阶面。绘制、人物脚下高度和高差碰撞共享体素网格。生成器在最终地形上检查各工坊和码头的路线。

工坊包含集市摊位、帐篷、木屋、船屋、玻璃花房、观测亭、图书屋、工作室，以及旅行书车、风铃廊亭、遗迹拱门、风车工坊、信号驿站、霓虹机房、蘑菇小铺和折纸工棚。结合练习类型随机安排，同岛优先选择不同外观；横幅按建筑高度留空，点击按钮在横幅上方保持固定像素间距。外观、标牌锚点与实体碰撞共用结构配方，保留完整工作区点击与长台碰撞，所有新增建筑仍走静态合批。工坊 NPC、村民和营地居民合计默认最多 8 个；航行时暂停 NPC 寻路。世界最多绘制两座岛，到达后释放上一座岛；场景帧率上限为 60，可在画面设置调整；练习打开时暂停重绘。左下角航线按钮打开地图列表，选择已解锁的岛会走向码头乘船；未解锁岛不能跳过任务进入，沉浸模式同样可用。

## 景观与探索支线

12 种 JSON 景观：草原、樱花、雪山、沙漠、溶洞、丘陵、风车平原、沙滩、熔火秘境、云上花园、丛林、赛博港。使用独立的植被结构、山石、水色和点缀；每岛最多 4 只动物或机器，可观察并记入图鉴。海面使用一批小方块组成的阶状波纹；减少动态效果偏好会冻结这些动画。每岛独立抽取清晨、午后、细雨、夜晚与极少的凌晨（权重 1%，且一条航程最多一次）。乘船切换时平滑变化太阳方向、阴影和轻度画面色调，保持夜间可读性。

每岛三块星图碎片和一座古老星灯，均放在可达道路旁。集齐碎片并完成任意一个完整工坊后，可挑战没有倒计时的星灯记忆，点亮星灯获得岛屿印章。累计 1、3、6 枚印章分别解锁樱花、极光、星夜船帆，可在收藏册随时换装。支线不影响启航条件，收藏与外观自动保存。

“寻找星图”按人物当前位置优先前往附近尚未收集的碎片；最近目标无法到达时，尝试下一个附近目标，不按碎片编号排序。收齐后按钮改为前往星灯；直接点击指定碎片仍会前往该目标。

山体按完整底座抬高并找平地形，避免只按中心高度放置。人物被树、山体或突出的高岸遮住时，显示顶层荧光描边。路径规划与移动共用扫掠碰撞，转角精确落在路点上；不可达目标返回失败提示，运行时有限次重规划，不会永久顶着障碍。

## 软件与操作练习

基础键鼠、文字编辑、选择、拖放、剪贴板、撤销、保存和截图，与本地模拟应用组合：

- 文档编辑：选中标题、加粗、居中、项目符号、补正文、保存。
- 文件资源管理器：目录树、路径栏与详情列表，新建文件夹、右键重命名、Ctrl/Shift 多选、剪切/复制/粘贴及拖放。
- 表格：填数、Tab 切格、SUM 求和、整表排序、可恢复的筛选、区域选择与柱形/折线/饼图。
- 演示软件：选版式、填标题、拖图片、预览。
- 邮箱：收件人、主题、正文、附件，以及收件箱阅读、保留原主题回复、草稿继续编辑和已发送记录。
- 日历：翻周、选择时段、新建/修改/删除日程、地点与提醒、重叠时段冲突提示。
- 设置与窗口：单选、复选、下拉、移动与缩放。
- 浏览器：地址栏输入网址或搜索词、多条结果比较、独立标签页与前进/后退历史、收藏命名与重访、页内查找、下载另存为与文件预览。
- 画图：工具、调色、鼠标拖绘和保存。
- PDF 阅读器：缩略图跳页、搜索、缩放、高亮批注。

应用练习均在游戏内运行。浏览器资料站不访问外部网站，邮箱不发出真实邮件。中文撤销使用 `！`，英文使用 `!`。

文件题使用独立的内存目录：新建后立即出现真实的练习文件夹，双击只导航，移动会改变原件位置，复制会保留原件。提交时核对目标文件夹的实际内容，误放的文件可以移回后重试；不会读写学生电脑上的文件。各题显示当前步骤、对应操作区域和具体错误反馈。后续文档、邮件带有可补全的草稿，表格提供部分已有数据，减少重复抄写。

37 个操作步骤重新设计，其中浏览器由单题扩展到 16 题。搜索不再要求固定唯一字符串，而是在本地资料中匹配关键词，并提供不同来源、日期的结果供比较；进入正文后还需完成本题操作再提交。回复邮件按内容要点核验，允许自己组织句子。图表按真实数值绘制，折线用于连续测试记录，饼图用于调查票数构成，柱形图比较类别。练习运行时只处理操作事件，没有轮询、动画循环或外部软件依赖。

81 个工坊的材料结合人工智能、信息科技与信息技术情境，覆盖信息意识、计算思维、数字化学习与创新、信息社会责任四个维度。例如查找 AI 回答的原始出处、记录传感器数据、拆解机器人指令、设计数字作品、匿名整理调查结果、检查素材授权，以及保护账号与截图隐私。文档正文、文件名、表格类别、邮件与附件、浏览器搜索资料、PDF 手册使用对应材料；英文输入练习保留简短句子。完成一个工坊后显示一句相关的学习提醒，不增加操作门槛。这些内容提供信息素养启蒙，不作为四个维度的能力测评。

## JSON 配置

`src/levels.json` 为配置版本 4，配有 `levels.schema.json`：

- `missions`：全程任务包，含主题、名称和至少三步任务 ID；`introduction` 标记引导任务；`literacy.dimension` 与 `literacy.tip` 定义信息素养维度及完成后的学习提醒。
- `islandNames`：仅用于随机命名，不决定岛屿数量。
- `landscapes`：草坡、溪谷、树林、海湾等地图参数与环境文案。
- `environments`：各时段天气的权重、太阳方向与强度、环境光、海色和天空颜色。
- `biomes`：景观名称、故事、植物类型、动物或机器种类、地表与山石调色板、树木和山体数量。独立洗牌循环，不改变任务分岛。
- `islands.workshopCount`：每岛容量，默认 `[1,6]`；`introductionCount` 默认 `[2,3]`。
- `islands.baseLayers`：随机岸体层数，默认 `[1,5]`。
- `islands.densities`：`scattered`、`mixed`、`clustered` 可组合。
- `islands.npcLimit`：NPC 总量上限，默认 8。
- `variants`：基于基础题型设置任务内容与参数，支持继续引用变体。

`src/curriculum.json` 定义基础主题和任务模板；`curriculum.js` 解析变体并校验引用；`journey.js` 负责课程分岛，`level-layout.js` 负责单岛布局。添加岛名不需要添加关卡，新增任务只需添加任务包和题目数据。

资料站通过题目 `params.siteName/address/query/resultTitle/summary/article/source` 配置；PDF 通过 `title/file/query/section/intro/passage/lastSection/lastBody` 配置。其他应用支持邮件 `attachment`、表格 `columnLabel/unit`、登记表 `nameLabel/countLabel`、资料包 `labels` 等显示文案参数，避免题目改了而练习界面仍使用旧材料。

`src/exercise-guides.json` 定义各题型的步骤文案及高亮目标，题目可用 `guide` 覆盖；`context` 提供情境，步骤从题目参数展开名称和目标。文件题使用 `params.files/targets/folder/operation`，其中 `operation` 为 `move` 或 `copy`；文档 `initialBody`、表格 `initialValues`、邮件 `draft` 定义开题时的已有内容。

浏览器的 `pages` 保存每条资料的 `id/address/title/source/date/summary/body/keywords`；`targetIds` 定义需查阅的资料，收藏用 `bookmarkName/bookmarkFolder`，页内查找用 `find`，下载用资料的 `download` 与题目的 `downloadName/downloadFolder`。数据表用 `rows` 保留稳定记录 ID，排序用 `sortField/sortOrder`，筛选用 `filterValue/targetIds`，图表用 `chartType/chartTitle`。回复邮件使用 `sender/requestSubject/requestBody/requiredPhrases/attachments/attachment`，日历使用 `date/start/end/eventTitle/place/reminder/busy`。这些操作的 UI 与判定分模块维护，课程仍由 JSON 组合。

## 存档与导出

localStorage 保存随机种子、航程版本、任务完成情况、练习次数和内容。旧固定四岛存档保留已完成任务和记录，重新分岛后从最早未完成的岛继续；新版刷新保持航程。毕业须完成全部 243 步，报告可导出 JSON。重新开始会清除当前进度并生成新航程。

原生复制、剪切、粘贴、撤销和文本选择由浏览器处理。Ctrl+S 写入游戏档案；截图只在本地展示，不上传。系统截图练习根据收到的图片完成，网页无法确认系统截图快捷键。

## 开发与轻量检查

```sh
npm install
npm run dev
npm test
npm run build
```

`npm test` 串行执行针对性检查，仅生成三张地图，检查随机分岛与名字解耦、存档、场景占地支撑、转角扫掠、不可达终点、高差与梯子通行、动作状态、画质降级、合批淡出与居民动作，以及凹凸岸线往返、跨岛礁石与船位净空。默认没有几百张地图压力测试。

性能排查可运行 `node scripts/profile-world-cpu.mjs`，用一张固定小岛执行短时实际游戏逻辑，记录行走、居民、遮挡、裁剪、缓存和标牌的 CPU 分段及更新次数，并保存 32 个连续移动帧的分段耗时和同帧工作。预热后的固定配置走动若出现整景重拍、同帧重复静态索引选择或静态投影重烘焙，脚本直接失败。它不创建浏览器、不生成随机地图，渲染器用空实现替换，输出到 `test-results/world-cpu-current.json`；这些时间不包含真实 WebGL、DOM 和 GPU，不能换算为设备 FPS，也不能代替真实渲染验收。

小船的船体和可换色帆共享一个绘制对象，换帆只更新帆对应的颜色范围；动态道具与静态装饰的批次先过滤无关更新，再执行矩阵计算。关闭漫步后，已冻结居民不再随装饰动画执行空模拟，招手、爬梯和重新开启漫步仍可唤醒居民；默认环境活动与画质不变。

每帧正常视图检查后，居民/动物/装饰动画引起的二次检查只访问变化对象；相机、岛屿位置或遮挡淡出缓存失效时仍完整检查。岸线净空使用保守的平方距离先筛选岛内与岛外位置，只在海岸带计算实际距离和多边形边，不改变通行余量。

岛景缓存复用时只合成整屏颜色，不再逐像素读取并写回整屏静态深度。人物、动物、船、透明场景、标牌、波浪、雨和脚影在实际覆盖的像素上读取缓存深度，活动物体之间保留硬件遮挡；顶层主角描边独立显示。环视、航行和重拍岛景关闭该检测，特殊深度材质回退到完整深度合成。默认 120% 分辨率，阴影与环境活动保持原配置，150% 仍可手动选择。

点击自动行走与键盘均支持斜向移动。自动寻路按角色沿线实际净空检查斜向边，不再要求旁边两条横纵网格同时空着；仍阻止穿过树干、封死的夹角和不可步行高差。最近网格点位于死角时，原搜索失败后尝试周围经过扫查的接入点，避免角色在树旁或拐角被错误判为无路；正常路线继续复用既有导航缓存与已验证的移动走廊。

开发版可在游戏运行时执行 `await window.__quest.world.profileFrames(60)`，按需采样 8–120 个已绘制帧，返回 CPU/帧间隔的均值、P95、P99、峰值、最慢 8 帧及全部逐帧记录。每帧同时记录六个逻辑/提交阶段、静态场景/活动层/索引选择/阴影提交的细分耗时，以及缓存补画面积、整拍、索引选择、阴影、居民规划、遮挡和路线验证次数。GPU 查询结果关联其原始帧，尚未可用的结果保留空值；不能拿上一帧 GPU 数据当作本帧证据。细分提交耗时包含在对应主阶段内，不应重复相加。报告分别记录 CPU 超预算、GPU 超预算和严重慢帧；帧间隔使用上一帧目标频率，忽略采样前的首个间隔及半毫秒边界波动，避免待机唤醒误报。

GPU 扩展不可用时仍返回 CPU 数据，报告明确保留 GPU 空值；最多 4 个待取查询，不等待 GPU。暂停、静止休眠或世界销毁会提前结束，以返回的 `reason` 和实际 `samples` 为准。未采样时不读取诊断时钟、不生成逐帧记录；正式构建移除采样器及逐段标记。具体摸排和证据见 [PERFORMANCE.md](PERFORMANCE.md)。正式版 FPS 面板显示 JS 提交均值及采样窗口峰值，仅在开启 FPS 或主动勾选自动减负时启用低频异步 GPU 计时，最多每秒一次、两个待取查询，不等待 GPU；两项均关闭时完全停用。

`node scripts/verify-exercise-polish.cjs` 使用无地图的应用夹具检查文件操作、引导与错误反馈，结束关闭浏览器及临时服务器；`node scripts/verify-file-offline.cjs` 在一张离线岛上验证正常文件题提交、XP 与存档。

`node scripts/verify-software-practice.cjs` 用无地图夹具检查 10 类软件操作与三种图表、错误修正、草稿恢复、日程冲突和窄屏布局，结束关闭浏览器及临时服务器；`node scripts/verify-software-offline.cjs` 在一张离线岛上检查新版浏览器的正常课程提交。

预览工具或扩展尝试注入资源时，CSP 拒绝该资源不等于游戏文件被修改，不再一律停机。解包时主动核对程序、样式摘要，运行时只观察游戏自身的启动器、数据、程序、样式和策略节点；拒绝加载的额外脚本、样式不参与合法游戏的完整性判定。`node --test tests/release-integrity.test.js` 使用内存中的极简 DOM 复现资源拦截与核心内容变更，不打开浏览器或生成地图。

整包 AES 密封和“缺少 API 就拒绝启动”的方案已移除。检查提示、事件名、选择器及预期署名改用 ChaCha20-Poly1305 认证加密：每个构建中的启动器和程序各生成独立随机 256 位密钥与 nonce，发布物不含这些检查字符串的明文或 Unicode 转义副本，开发源码仍保留可读文本。离线内置纯 JS 解密（@noble/ciphers），仅在两个模块初始化时各解密一次，后续检查复用字符串常量；密钥随客户端交付，因此这是静态字符串保护，不是对文件所有者保密。

gzip 解包使用随文件内置的纯 JS 实现（fflate），SHA-256 也有本地纯 JS 实现；不要求 `crypto.subtle` 或 `DecompressionStream`。完整程序摘要只在创建会话时计算一次，业务边界复用摘要结果并核对当前节点/内容，不在帧循环做解压、解密、摘要或 DOM 轮询。压缩不是校验手段，离线代码可以正常解包查看；可见署名及 HTML/CSS 标记仍按用途保留。

这是提高直接编辑和删除检查的成本，不能为完全由接收者控制的离线文件建立可信执行边界：逐一重写所有业务提交点、重新构建程序，或在所有检查前执行并隐藏脚本仍可绕过。若需要不可伪造的发行身份，必须使用受信任的外部启动器/签名分发或受控服务端。合法源码更新后应重新运行 `npm run build`。`node scripts/verify-credit.cjs --built` 检查正常弹窗、运行中停机、删除/隐藏署名；`node scripts/verify-sealed-build.cjs` 检查离线删改及两项原生 API 同时不存在；5174 开发服务器下运行 `node scripts/verify-session-flow.cjs`，以真正空置关闭函数的游戏验证 XP/启航拒绝、正常乘船和静止期间零检查读取。均使用短场景，不跑随机地图批量测试。

五轮进一步打磨及定向证据见 [PERFORMANCE.md](PERFORMANCE.md)。`node scripts/verify-render-polish.cjs` 仅用几个方块验证 150% 下的动态投影、透明过渡和缓存/完整重绘像素一致性，不生成地图。

进一步减少高分辨率固定开销：静态缓存复用与 FXAA 输出直接覆盖整屏，不再提前清空颜色/深度缓冲；阴影按已绘制姿态的实际变化刷新，呼吸和轻微船身摆动不触发重拍，停止动作的最后姿态仍会补画。运行时导航器按岛复用网格净空和邻边检查，终点及平滑路线保持精确校验；切岛释放缓存。阴影准备阶段的 1 像素颜色通道使用极简裁剪材质，真实阴影保留原始投射材质。

缓存复用帧仅更新角色及标牌的裁剪；静态空间索引只在真正重拍岛景或完整绘制时更新，避免主镜头和缓存余量视图之间反复上传索引。FPS 显示和帧率上限变更保留自适应档位及静态缓存。阴影辅助通道在真实投射之后使用空颜色范围，结束后恢复共享几何，不再重复提交无用的顶点。

环境活动开启时，动态阴影改变优先局部补画岛景：把投射物旧、新位置向最低地面投影，覆盖高地侧面及阴影过滤边缘，合并重叠矩形，只清除和重画这些范围的颜色、深度及静态空间块。大范围变化、时段变化、缩放和切岛仍完整更新。太阳阴影贴图按原预算刷新，居民、动物、装饰和高档动态投影均可继续活动。

居民站立时的轻微呼吸由顶点着色器完成，休息期间不再反复采样地形、遍历肢体和上传整个居民网格；行走、招手和爬梯仍更新真实姿态。居民、动物选择目标时验证完整直线走廊，随后按原直线推进，避免每走几厘米就再次扫查同一静态碰撞区域；偏离、目标修改、半径变化及梯子出口重新验证。玩家的任意方向移动仍保留逐步碰撞检查。

`node scripts/verify-active-environment.cjs` 使用一个投影夹具和一张固定小岛，短时检查环境活动保持开启、局部重绘/完整绘制像素一致性、旧投影清除、高台和镜头平移，以及招手、屏外零模拟和零道具上传。没有随机地图、CPU 限速或长时间 FPS 压力负载；工作量对照见 `PERFORMANCE.md`。

主角身体和肢体共享一个绘制批次，通过六个局部姿态矩阵在顶点着色器中变换；居民、动物和活动道具通过小型浮点姿态表完成位置与法线变换，走路、招手、爬梯不再重传整个人物的顶点。源骨架继续驱动拾取、碰撞和荧光描边，动态阴影使用相同姿态。礁石、灯座、信标等静态道具进入岛景缓存，点亮、完成状态或可见性变化时才刷新。雨滴与波浪位置由 GPU 计算；波浪按当前相机象限仅保留顶面和两个可见侧面，并按镜头在海面的范围提交网格单元，放大后不再计算远处全部波浪，保持世界坐标中的密度和连续漂移。环视时直接绘制当前可见区域，松手平滑回到主视角及缓存复用，避免拖动时反复重拍大张缓存。角色静止、相机不变和地形不可能遮挡的范围跳过对应工作。岸线查询预先保存多边形边系数，并用保守内外圆排除常见情况，保持原有通行边界和安全距离。

`node scripts/inspect-frame-cost.cjs` 只用一张固定 22×22 小岛，短时采样 1.2 秒，保留居民、动物、雨滴、波浪和烘焙组合；记录 CPU 调用栈样本、绘制/上传计数及两个烘焙选项的真实像素变化。它不是低端机 FPS 达标测试。
